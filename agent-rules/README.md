# Agent rules

`UNIVERSAL.md` is the source for the root `AGENTS.md` that the `workspace` skill installs; the root `CLAUDE.md` is a symbolic link to it. It imports the workspace's own `WORKSPACE.md`.

`skill-protocols/` holds one protocol per skill: `domain-modeling`, `grill-with-docs`, `grilling`, `prototype`, `research`, `retro`, `to-tickets`, and `wait-what`. A protocol holds only checks that its skill is called and run as written: the Skill tool calls it makes, a check per step or format of the skill, and the skill's own end. Behaviour the skill lacks goes into an extension skill, `skills/<skill>-ext/`, never into a protocol or a rule; the protocol names it in `with:`, and the hook adds the extension skill whole, or at one step (see step loading below); a skill the dev does not own stays unedited. Each protocol's first line is the marker `<!-- managed by dev-skills: agent-rules/skill-protocols/<name>.md -->`, which tells a managed copy from a workspace's own file.

A skill typed by the dev starts a new stage: its protocols replace the active set. A protocol whose header holds `kind: side-quest` marks its skill as a side quest instead: typed inside a stage, it keeps the stage's protocols and extension skills in force, on that prompt and on later ones, and its own protocol joins them on the prompt that types it. `prototype`, `research`, and `wait-what` are side quests.

Step loading: a protocol loads one step at a time when its body holds steps. Each step opens with the line `## Step: <name>`. The next line is its completion criterion: `done: <Tool>` is met by any call of that tool, and `done: <Tool> <input field> ~ <regex>` by a call whose input field matches the JavaScript regex, for example `done: Bash command ~ gh issue create`. Give every step a criterion except the last; a step without one stays current until its stage ends. The current step is the first step whose criterion no tool call has met since the protocol's stage started. On each prompt the hook injects the text above the first step plus the current step only. After a tool call that meets the current step's criterion, the hook injects the next step. The hook reads steps from the transcript alone, so agents write no step markers. A protocol with no `## Step:` line loads whole. To tie an extension skill to one step, write `<extension>@<step name>` in `with:`, for example `with: [retro-ext@gather]`: the extension skill's text loads with step `gather` and is absent before it.

`platforms/` holds settings fragments. The skill merges a fragment only where the platform supports it, into the workspace's personal settings (`.claude/settings.local.json` for Claude Code), and preserves workspace-owned settings. Its `<pinned>` placeholder stands for the workspace's pinned copy, `.agent-rules/dev-skills/`, which the `workspace` skill extracts from `origin/<default>`; hooks never run from this working tree, so its branch and local changes reach no workspace. `platforms/claude-code.json` denies `AskUserQuestion` and `mcp__ccd_turn__wrap_up` because the dev prefers not to use them; agents ask in plain chat instead. That is a personal preference, which is why the fragment goes into personal settings and not into a workspace's shared ones. Its hooks run `hooks/skill-protocol.mjs` on every prompt and after every call of a tool its PostToolUse matcher names: `Skill` and each tool a step criterion names. A test fails when a criterion names a tool outside the matcher. The script adds the protocols of the session's active skills from each `.agent-rules/skills/` between the session's folder and `/`, the nearest one winning per skill. Test it with `node --test agent-rules/hooks/skill-protocol.test.mjs`. The fragment also runs `hooks/steering-changed.mjs` at session start and on every prompt, which names the steering files and the repositories' `AGENTS.md`, `CLAUDE.md` and `GLOSSARY.md` that changed on disk since the session last checked, and `hooks/no-host-paths.py` before every write and command, which blocks a path of the dev's machine from entering a repository of the workspace. Test them with `node --test agent-rules/hooks/steering-changed.test.mjs` and `python3 -I agent-rules/hooks/no-host-paths.test.py`. Its Stop hook runs `hooks/grill_round_check`, which blocks a turn whose grill round breaks the format of `grilling` and `grilling-ext`. It finds a re-asked question by its title in the grill's earlier turns, compares the text after its `❓ **Qn**` tag with that last ask, whitespace collapsed, and blocks a question that differs and has no `Rewritten:` line; test it with `cd agent-rules/hooks && uvx pytest tests`.

`retro-pool.md` is the format of the Retro pool: its place, layout, index, states and entry template. The pool holds every problem and good practice gathered from sessions, one entry each, and a retro draws on it. It is one folder, `retro-pool`, in the workspaces' parent folder, with its own local git and no remote; a workspace in another parent folder names it in `env.RETRO_POOL` of its personal settings. The `workspace` skill's setup and sync create the pool when it is missing, and the pinned copy carries this format to every workspace. The pool's data stays on the dev's machine: only its format lives here.

`retro-ext` (`skills/retro-ext/`) is the extension skill that gathers a session into the Retro pool. A session skill's protocol ties it to its end step, as `to-tickets` does with `with: [retro-ext@gather]`, so its text loads only after the step before it is done. Its text tells the agent to start one gathering sub-agent with the transcript path, the active skill and the workspace, and to show the dev the one line it returns. The hook writes the session's transcript path where an injected text holds `<transcript-path>`. The gathering brief, `skills/retro-ext/GATHERING.md`, is read only by that sub-agent; it is not injected. It reads the transcript and its subagent transcripts, records each problem, good practice and skipped step as an occurrence, appends it to a matching entry that is not closed or creates a new entry, and commits in the pool. It counts tokens as bytes divided by 4, the rule of `tools/token-limit-check.sh`. `retro-ext` names no skill, so any session skill's protocol can tie it to its end step.

`templates/WORKSPACE.md` starts a fresh workspace's own rules.

`steering/` holds what steering needs: `exclude`, the allow-list of the workspace's own files; `exclude-folder-root`, the folders added when the workspace root is not a repository; and `steering`, the git wrapper copied to `.agent-rules/steering`.

`workspaces.local.tsv` lists the workspaces registered on this machine for `sync`, one per line: the workspace name, a tab, its absolute path. Git ignores it, so personal paths stay out of the repository.

`tools/token-limit-check.sh` is a pre-commit check a repository can install: it blocks a staged file over 5,000 tokens and says how to split it.
