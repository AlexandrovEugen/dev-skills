# Agent rules

`UNIVERSAL.md` is the source for the root `AGENTS.md` that the `workspace` skill installs; the root `CLAUDE.md` is a symbolic link to it. It imports the workspace's own `WORKSPACE.md`.

`skill-protocols/` holds one protocol per skill: `domain-modeling`, `grill-with-docs`, `grilling`, and `retro`. A protocol holds only checks that its skill is called and run as written: the Skill tool calls it makes, a check per step or format of the skill, and the skill's own end. Behaviour the skill lacks goes into an extension skill, `skills/<skill>-ext/`, never into a protocol or a rule; the protocol names it in `with:`, and the hook adds the extension skill whole; a skill the dev does not own stays unedited. Each protocol's first line is the marker `<!-- managed by dev-skills: agent-rules/skill-protocols/<name>.md -->`, which tells a managed copy from a workspace's own file.

`platforms/` holds settings fragments. The skill merges a fragment only where the platform supports it, into the workspace's personal settings (`.claude/settings.local.json` for Claude Code), and preserves workspace-owned settings. Its `<pinned>` placeholder stands for the workspace's pinned copy, `.agent-rules/dev-skills/`, which the `workspace` skill extracts from `origin/<default>`; hooks never run from this working tree, so its branch and local changes reach no workspace. `platforms/claude-code.json` denies `AskUserQuestion` and `mcp__ccd_turn__wrap_up` because the dev prefers not to use them; agents ask in plain chat instead. That is a personal preference, which is why the fragment goes into personal settings and not into a workspace's shared ones. Its hooks run `hooks/skill-protocol.mjs` on every prompt and every Skill call: the script adds the protocols of the session's active skills from each `.agent-rules/skills/` between the session's folder and `/`, the nearest one winning per skill. Test it with `node --test agent-rules/hooks/skill-protocol.test.mjs`. The fragment also runs `hooks/steering-changed.mjs` at session start and on every prompt, which names the steering files and the repositories' `AGENTS.md`, `CLAUDE.md` and `GLOSSARY.md` that changed on disk since the session last checked, and `hooks/no-host-paths.py` before every write and command, which blocks a path of the dev's machine from entering a repository of the workspace. Test them with `node --test agent-rules/hooks/steering-changed.test.mjs` and `python3 -I agent-rules/hooks/no-host-paths.test.py`. Its Stop hook runs `hooks/grill_round_check`, which blocks a turn whose grill round breaks the format of `grilling` and `grilling-ext`; test it with `cd agent-rules/hooks && uvx pytest tests`.

`templates/WORKSPACE.md` starts a fresh workspace's own rules.

`steering/` holds what steering needs: `exclude`, the allow-list of the workspace's own files; `exclude-folder-root`, the folders added when the workspace root is not a repository; and `steering`, the git wrapper copied to `.agent-rules/steering`.

`workspaces.local.tsv` lists the workspaces registered on this machine for `sync`, one per line: the workspace name, a tab, its absolute path. Git ignores it, so personal paths stay out of the repository.

`tools/token-limit-check.sh` is a pre-commit check a repository can install: it blocks a staged file over 5,000 tokens and says how to split it.
